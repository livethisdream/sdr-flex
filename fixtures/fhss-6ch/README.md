# Frequency hopping, 6 channels

A hopper walking six channels 25 kHz apart, dwelling sixteen symbols on each, carrying
2-FSK at 2400 baud with a 2.4 kHz shift. 200 kS/s complex on 433.92 MHz.

The hop order comes from a shift register rather than a random draw, because that is what
a real hopper does — both ends walk a sequence they already agree on, every channel gets
visited, and the order is not obvious. Finding that order is the thing somebody analyzing
a hopper is usually after.

**The payload runs continuously across the dwells.** That is the whole point of the
fixture: a modulator that restarted a packet on every dwell would make de-hopping
unnecessary, and a de-hopper that could not recover the payload would look like it
worked. The suite checks both directions — the same chain pointed at this capture
*without* de-hopping first recovers nothing.

Dwells are a whole number of symbols, because that is how a hopper is built: the
frequency changes between symbols and never part-way through one.

**Nobody transmitted this.** Generated by `fixtures/make.mjs` from a fixed seed; it
regenerates byte for byte.
